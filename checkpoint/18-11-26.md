Three major changes are planned:

```text

```

Changing all three simultaneously would make debugging unnecessarily difficult.

Example:

```text

```

Possible causes would become:

```text

refactor failed

```

Instead the migration must be staged.

Correct approach:

```text

   ↓
prove Remote API
   ↓
same logic in TS
   ↓
prove TS toolchain
   ↓
refactor architecture
```

This preserves causal clarity.

# 14. Known neofetch bug

Current code contains:

```js
const hskill = ns.getHackingLevel(thost);
```

However, the current Netscript API uses:

```ts
ns.getHackingLevel()
```

without a hostname argument.

Correct form:

```ts
const hskill = ns.getHackingLevel();
```

This is exactly the class of bug TypeScript can detect before runtime.

With correct Netscript typings, code like:

```ts
ns.getHackingLevel(thost)
```

should generate an error similar to:

```text
Expected 0 arguments, but got 1.
```

This is one of the strongest immediate demonstrations of why TypeScript migration is valuable.

# 17. Future JIT5 philosophy

JIT5 should not simply mean:

```text
JIT4 + more features
```

The core improvement should be:

> adaptive closed-loop optimization.

Current JIT architecture already models expected income.

The next step is comparing prediction to reality.

Example:

```text
Predicted income : $90m/s
Real income      : $71m/s

Efficiency       : 78.9%
```

The engine should then react.

If real efficiency drops:

```text
reduce take %
increase landing gap
reduce number of lanes
repair target
recalculate
rebenchmark
```

If the system remains stable:

```text
reduce gap
increase take %
evaluate another lane
increase aggressiveness
```

The objective becomes:

```text
maximize real stable $/second
```

not:

```text
maximize RAM usage
```

and not:

```text
maximize target count
```

```text

      ↓

      ↓

```
