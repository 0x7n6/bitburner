## Runtime contract

| Component | Current behavior |
| --- | --- |
| `ap.ts` | **JIT6 dashboard**, **JIT6 sessions** and **Progression tools** are the normal entry points. It exposes current services, RAM, Source-Files, recent JIT6 decisions, faction details and reset readiness. Legacy production starters are out of the normal AP launch path. |
| `jit6.ts` | Preview reads admission state. An execution session admits work against live RAM, a shared deadline, process ownership and the current reset generation. It checks emergency RAM for `stopfarm.ts`. A lighter free-study worker can fit when the full pilot is too large and the purchase budget is zero. |
| `bt4-plan.ts` and `bt4-auto.ts` | The plan reads current joined factions, sellers, prices, reputation and prerequisites. The pilot prioritizes The Red Pill on the standard route and chooses a modeled work type when Formulas.exe is available. An authorized purchase session can queue up to eight eligible augmentations with live quotes, a total cap and a cash floor. |
| Player work | A JIT6 child waits for the existing activity before starting new work. It yields if the player takes over its work. An authorized budget can queue eligible purchases while existing work continues. The original class can keep the work slot occupied for the full session. |
| Share and Trader | Share admits at least one thread when space remains after measured control headroom and any pending Trader reserve. Managed Share gives back threads as RAM demand rises. Trader is opt-in, requires TIX and 4S TIX and uses a positive cash floor. A Trader session excludes augmentation and home-upgrade spending budgets. |
| Pause and resume | `stp` writes the pause state on `home`, stops managed processes and holds mission-owned Trader positions. `stp-rs` starts a fresh 15-minute work-only session. It never starts the legacy bootstrap. `stp-os` is the path to stop a legacy supervisor still running. |
| Catalog and resets | The version-pinned catalog covers 15 BitNodes and 34 factions. Live faction fields and multiplier data follow the save's API access. Reset readiness shows the queue, Red Pill status and active services. Installation and BitNode selection use the game UI. |
| Production and Darknet | JIT6 coordinates progression and optional services. JIT5's batch production has no JIT6 replacement in this release. Darknet is covered by readiness and instability observations, plus the BN15 alternate Red Pill guide. Find V1/V2 remain manual tools. |

## Review against official and community sources

- **Engineering direction.** A scheduler with small workers matches the RAM cost of using Singularity outside BN4. SF4 levels 1–3 give 16×, 4× and 1× cost respectively. The tested path preserves game activity ownership and checks actual RAM. [Official SF4 definition](https://github.com/bitburner-official/bitburner-src/blob/3162fd2590e221eadd0c0fbd46151913f7c4c41c/src/BitNode/BitNode.tsx#L155-L167)
- **Progression.** Recent BN4.2 experiences use attainable augmentation goals and favorable points to install. Alain Bryden's reference also considers work rate, favor and the reputation needed to unlock donations. JIT6 models the work for a selected augmentation. Ranking different targets by time and projecting the value of an install cycle are pending. [BN4.2 community discussion](https://www.reddit.com/r/Bitburner/comments/1xm7cgi/working_on_bn42_question_about_factions/) · [Community reference in `sources/`](../sources/alainbryden/work-for-factions.js#L895-L980) · [Official favor rules](https://github.com/bitburner-official/bitburner-src/blob/3162fd2590e221eadd0c0fbd46151913f7c4c41c/src/Documentation/doc/en/basic/reputation.md)
- **Confirmed planner gap.** A read-only fixture with an affordable and rep-eligible Neuroreceptor Management Implant returned `score=0` and `useful=false`. Its effect on unfocused faction work is special and provides no weighted numerical stat. The automatic plan skips it unless it becomes part of a weighted prerequisite chain. NeuroFlux is also excluded from automated ranking. Any future scoring change should preserve purchase caps and distinguish augmentation count from upgrade levels. [Official implant definition](https://github.com/bitburner-official/bitburner-src/blob/3162fd2590e221eadd0c0fbd46151913f7c4c41c/src/Augmentation/Augmentations.ts#L1229-L1240)
- **Share.** The pinned API increases active faction work reputation. The current scheduling gate is RAM and owner admission, so an optional Share session can use RAM while the character is studying. Measure its benefit when faction work is active. [Official Share API](https://github.com/bitburner-official/bitburner-src/blob/3162fd2590e221eadd0c0fbd46151913f7c4c41c/markdown/bitburner.ns.share.md)
